# 双环 PID 定速定位置控制 —— 调试 BUG 记录与原理解析

---

## 1. 遇到的现象

系统初始时 Target（目标值）、Actual（实际值）、OuterOut（外环输出）和 PID 输出均为 0。

但是用手拧动转盘时，圆盘非但没有产生阻力反向纠偏，反而**瞬间顺着拧动的方向极速旋转**起来，且几乎不会停下（进入失控饱和状态）。

> **神奇的是**：整个系统没有修改任何硬件接线和编码器物理极性，仅仅将变量类型 `uint16_t` 改为 `int16_t` 后，BUG 就彻底解决了，手拧转盘在两个方向上都能感受到正常的阻力。

---

## 2. 根因分析：由无符号整型溢出引起的"伪正反馈"

在控制系统里，极性原本是正确的（即物理上本就是负反馈系统）。但由于使用了无符号数据类型，导致在特定情况下，**负反馈在计算上被扭曲成了正反馈**。

## ① 为什么往正方向拧没事，而往负方向拧会失控？

**往正方向拧（如速度为 `+5`）：**

`+5` 在 `uint16_t` 也是 `5`，PID 计算误差：

$$\text{Error} = \text{Target}(0) - \text{Actual}(5) = -5$$

由于误差为负，系统输出负的控制量（如 `-10`），电机产生反向力，手能感受到阻力。此时系统是正常的。

**往负方向拧（如速度为 `-5`）或系统产生微小的负向抖动：**

负数 `-5` 在内存中以补码二进制 `1111 1111 1111 1011`（十六进制 `0xFFFB`）存储。因为变量被定义为无符号数 `uint16_t`，编译器会将 `0xFFFB` 解释为正数：

$$2^{16} - 5 = 65531$$

此时实际值被误读为一个 **超级大的正数**。

## ② 误差极性的反转（"伪正反馈"的诞生）

当实际值被误读为 `65531` 时，PID 计算误差：

$$\text{Error} = \text{Target}(0) - \text{Actual}(65531) = -65531$$

- **本应输出**：因为是往负方向拧，系统应该输出 **正控制量**（拉回零点）。
- **实际输出**：由于计算出的误差是巨大的负数（`-65531`），PID 的比例项瞬间输出 **最大负控制量**（达到 `-100` 限幅极限）。
- **结果**：电机全速向负方向（顺着你拧的方向）旋转。这一旋转导致速度和位置负得更多，在无符号数解释下，数值依然是极大的正数（如 `65530`），PID 便持续输出最大负向占空比。
- **现象**：系统自己向着偏差方向疯狂加速，形成了致命的 **正反馈**，永不停息。

---

## 3. 更换为 `int16_t` 为什么彻底解决了问题？

将 `Speed` 改为 `int16_t`，`Location` 改为 `int32_t` 之后：

1. **原样保留了内存中的二进制补码** —— `-5` 的二进制依然是 `0xFFFB`。
2. **编译器正确解释了符号** —— `0xFFFB` 被识别为 `-5`。
3. **误差计算回归真实**：

   $$\text{Error} = \text{Target}(0) - \text{Actual}(-5) = 5$$

   因为误差为正，PID 正确输出正的控制量，驱动电机产生反向力（正向力）抵抗负向拧动。

4. **结论**：不论往哪个方向拧动，PID 算出的控制量方向都与偏差方向相反，手拧时便在两个方向上都能感受到纠偏的阻力，系统重回稳定的负反馈状态。

---

## 4. 经验总结

> 在编写嵌入式闭环控制系统（如 PID）时，**凡是涉及传感器反馈、速度、位置等有方向的物理量，必须定义为有符号数据类型（如 `int16_t`、`int32_t`、`float`）**。
>
> 一旦误用无符号数（`uint`），当物理量穿过 0 点变为负数时，会产生毁灭性的溢出，导致控制极性瞬间反转并引起系统失控。

# 双环 PID 为什么能同时实现定速与定位置控制？

## ① 首先理解"单环"各自能做什么

| 控制环             | 输入（目标值）          | 反馈（实际值）        | 输出                         | 能力                                              |
| ------------------ | ----------------------- | --------------------- | ---------------------------- | ------------------------------------------------- |
| **速度环（内环）** | 目标速度 `InnerTarget`  | 编码器增量 `Speed`    | PWM 占空比 → 电机转速        | 让电机 **以指定速度旋转**                         |
| **位置环（外环）** | 目标位置 `OuterTarget`  | 累计位置 `Location`   | 一个"期望速度"值 `OuterOut`   | 计算出"为了到达目标位置，**应该以多快的速度移动**" |

- 如果只有 **速度内环**：你可以让电机稳定在某个转速，但它不知道自己在哪里，无法停在某个位置。
- 如果只有 **位置外环** 直接输出 PWM：位置虽然能闭环，但速度不受约束 —— 位置误差大时，PID 输出一个很大的 PWM，电机会猛冲过头；误差小时又响应不足。中间的 **速度根本不可控**。

## ② 级联的核心思想：外环"指挥"内环

双环 PID 的关键在于这一行代码：

```c
InnerTarget = OuterOut;   // 外环的输出值 → 内环的目标值
```

这行代码的含义是：

> **位置环不直接驱动电机，而是告诉速度环"你现在应该跑多快"。速度环再负责让电机精确地跟上这个速度指令。**

这就像一个 **导航系统与油门踏板的关系**：

- **导航（外环 / 位置环）**：根据"你在哪里"和"你要去哪里"的偏差，告诉你"应该加速还是减速，大概开多快"。
- **定速巡航（内环 / 速度环）**：接到导航给的速度指令后，精确地控制油门，让车速稳定在指令值上。

## ③ 动态过程：从"远离目标"到"精准停住"

假设当前位置是 `0`，目标位置是 `+300`（向正方向转大半圈）：

---

**阶段 1 · 距离目标很远**

$$\text{位置误差} = 300 - 0 = 300 \quad (\text{很大})$$

$$\text{外环输出} = K_p \times 300 = 0.3 \times 300 = 90 \quad \xrightarrow{\text{限幅}} \quad \text{OuterOut} = 20$$

外环输出被限幅到 `20`，作为内环目标速度。这个限幅非常重要 —— **它限制了电机的最大速度**，防止因位置误差过大而让电机失控猛冲。

内环收到 `InnerTarget = 20` 后，通过 PID 控制精确地将电机速度稳定在 `20` 附近。

> → 效果：电机 **匀速、平稳** 地向目标位置移动。**这就是"定速"的含义。**

---

**阶段 2 · 接近目标**

$$\text{位置误差} = 300 - 250 = 50 \quad (\text{减小了})$$

$$\text{外环输出} = 0.3 \times 50 = 15$$

外环输出变小了，内环目标速度变为 `15`，电机开始 **自动减速**。

> → 效果：越接近目标，速度越慢，避免冲过头。

---

**阶段 3 · 非常接近目标**

$$\text{位置误差} = 300 - 298 = 2 \quad (\text{接近于 0})$$

$$\text{外环输出} = 0.3 \times 2 = 0.6$$

内环目标速度只有 `0.6`，电机 **以极低的速度缓慢爬行** 到目标位置。

---

**阶段 4 · 到达目标**

$$\text{位置误差} = 300 - 300 = 0$$

$$\text{外环输出} = 0 \quad \Rightarrow \quad \text{InnerTarget} = 0$$

内环目标速度为 `0`，速度环让电机 **精确地停住**。

如果此时用手拧转盘使位置偏离，外环立刻计算出新的位置误差，产生一个纠偏速度指令，内环驱动电机反向旋转将位置拉回来。

> → 效果：这就是"定位置" —— **电机像弹簧一样锁定在目标位置上。**

## ④ 微分项的作用：防止过冲振荡

注意外环参数中 `OuterKd = 0.4`，微分项的作用是 **提前刹车**：

$$\text{微分项} = K_d \times (\text{Error}_0 - \text{Error}_1)$$

当电机高速接近目标位置时，位置误差在快速减小（$\text{Error}_0 - \text{Error}_1 < 0$），微分项产生一个 **反向的制动力**，相当于告诉速度环"马上要到了，提前减速！"，从而抑制过冲和振荡，让停车更加平稳。

## ⑤ 总结：双环级联的三大优势

1. **自动"定速"**：外环的限幅（`±20`）天然限制了电机的最大运行速度；内环的速度 PID 保证电机实际转速精确跟踪这个速度指令。无论位置误差多大，电机都不会超速猛冲。

2. **精准"定位置"**：外环根据位置误差动态调整速度指令 —— 远离目标时快走，接近目标时慢走，到达目标时停住。这种"远快近慢到停"的行为，就是定位置控制的本质。

3. **解耦与鲁棒性**：把"去哪里"（位置环）和"怎么去"（速度环）分成两个独立的控制问题。外环只需要关心位置偏差，不用操心电机的电气特性；内环只需要关心速度跟踪，不用理解全局的位置目标。两者各司其职，系统更稳定、更容易调参。

> **一句话总结**：外环算出"该跑多快"，内环保证"确实跑这么快" —— 级联配合之下，电机就像一个既听话、又知道目的地的"智能司机"，自动完成 **加速 → 匀速 → 减速 → 停车** 的全过程。

#  进阶思考：可以将位置作为内环、速度作为外环吗？

**答案是：不可以（在常规的 PID 级联控制逻辑下是完全行不通的）。**

在所有的多环（级联）控制系统中，谁做内环、谁做外环，是有着严格的物理定律和逻辑要求的，绝对不能随意颠倒。具体原因主要有以下两点：

## ① 物理上的因果与积分关系（外环必须是内环的积分）

在物理世界中，**位置是速度的积分**（位置 = 速度 × 时间的累加）。级联 PID 的一个基本定律是：**外环控制的物理量，必须是内环物理量的积分。** 也就是说，内环控制的是外环的变化率。

- **正确的逻辑（外环位置，内环速度）**：
  外环（位置环）发现：“我距离目标还有 100 米”。于是它计算出：“为了走完这 100 米，**我需要以 5 米/秒的速度前进**”。然后它把 `5 米/秒` 作为目标指令发给内环。内环（速度环）负责驱动电机，精确保持 `5 米/秒` 的速度。这是完全合理的因果关系。

- **错误的逻辑（外环速度，内环位置）**：
  外环（速度环）发现：“我现在速度是 0，目标速度是 5 米/秒”。于是它计算出：“为了达到这个速度，**我需要去到位置 X**”。然后它把 `位置 X` 作为目标发给内环。
  这就非常荒谬了——为了保持一个恒定的速度，目标位置必须是无穷无尽地、每时每刻都在向远方增加的。外环的输出就会变成一个无限膨胀的数值，内环永远在追赶一个不断逃跑的位置目标，这就不再是 PID 调节，系统会直接崩溃。

## ② 响应频率的要求（内环必须比外环快）

级联 PID 的另一个铁律是：**内环的响应速度（动态特性）必须比外环快得多**（通常要求内环带宽是外环的 3~10 倍）。

- **速度的变化是很快的**：给电机加电压，转速瞬间就能提上来。
- **位置的变化是很慢的**：电机要转好几圈，位置才能慢慢累加到一个较大的值。
- **正确的逻辑（速度在内，位置在外）**：因为内环（速度）响应快，当外环（位置）给出速度指令时，内环能 **瞬间** 让电机达到该速度。外环看来，内环就像一个完美的"执行器"，指哪打哪，系统非常稳定。
- **错误的逻辑（位置在内，速度在外）**：如果把响应慢的位置作为内环，响应快的速度作为外环。外环（速度）发现速度不够，瞬间输出了一个目标位置给内环。但是内环（位置）动作太慢了，还没走到那个位置，外环一看"怎么速度还没上来？"，又给出了更夸张的目标位置。这样内环永远跟不上外环的节奏，系统会发生剧烈的震荡和失控。

## 💡 工业界的三环标准

正因为上述的物理规律，在真正的工业伺服电机控制中，控制环的顺序永远是固定死、从外到内依次嵌套的：

1. **最外环：位置环**（最慢，根据位置误差输出 **目标速度**）
2. **中间环：速度环**（较快，根据速度误差输出 **目标电流/扭矩**）
3. **最内环：电流环**（极快，根据电流误差输出 **PWM 占空比**）

在本项目中，由于没有做电流环，所以只保留了外面的两环，即 **位置外环 + 速度内环**，这也是最经典的双环控制架构。

# 进阶探讨：双环 PID 的调控周期应该怎么设置？

在多环控制系统中，PID 的执行频率（即采样与计算周期）直接影响系统的稳定性和抗干扰能力。关于内外环周期的设置，工业控制领域有一个核心原则：**内快外慢（外环周期通常是内环周期的 3~10 倍）。**

## ① 为什么必须“内快外慢”？

- **内环是外环的“执行器”**：外环计算出一个“期望速度”指令后，需要依靠内环去执行。内环必须有极快的响应速度，趁着目标速度还没改变，赶紧把电机的实际速度调整到位。
- **防止控制指令“打架”**：如果外环的更新频率等于甚至快于内环，就会出现这种情况：外环刚下发一个速度指令，内环的电机因为惯性还没来得及提速，外环一看“怎么位置没动？”，立刻又下发了一个更夸张的速度指令。这会导致内环一直处于剧烈的动态调整和追赶中，系统极易发生严重过冲和高频振荡。

## ② 典型的工业界经验值

由于电气变化 > 机械速度变化 > 宏观位置变化，工业伺服驱动器的周期通常如下设置：

- **电流环（最内环）**：电气响应极快，周期一般为 **100μs ~ 500μs**（控制频率 2kHz ~ 10kHz）。
- **速度环（中间环）**：机械响应稍慢，周期一般为 **1ms ~ 5ms**（控制频率 200Hz ~ 1kHz）。
- **位置环（最外环）**：宏观机械运动最慢，周期一般为 **5ms ~ 20ms**（控制频率 50Hz ~ 200Hz）。

## ③ 结合本项目代码的分析

回顾本项目的 `main.c` 中断函数设计：

```c
// ... 在 1ms 的定时器中断内 ...
Count1++;         
if (Count1 >= 40) // 速度内环：40ms 进一次
{
    // ... 速度 PID 计算 ...
}

Count2++;         
if (Count2 >= 40) // 位置外环：40ms 进一次
{
    // ... 位置 PID 计算 ...
}
```

在目前的代码中，**内环（速度环）和外环（位置环）的周期都被设置为了相同的 40ms。**

* **目前的做法可行吗？** 
  在精度要求不高、响应要求不极端的教学级直流电机控制中，内外环同周期是可以稳定工作的，因为电机本身的机械惯性天然起到了低通滤波的作用。此外，霍尔编码器的分辨率通常不高，如果速度采样周期太短（例如 1ms），每次读到的脉冲数极少，速度反馈的误差就会极大。因此，放大到 40ms 读取一次是为了让速度反馈数值足够大且更准确。

* **优化与进阶建议**：
  从严格的控制理论来看，如果未来换用高分辨率编码器（如光电编码器或磁编码器），建议将两环周期分离开来。例如：
  - **速度内环**：设置 `Count1 >= 10`（**10ms 运算一次**）。内环跑得快，能迅速抵抗负载波动和摩擦力阻力，精准锁死转速。
  - **位置外环**：设置 `Count2 >= 40`（**40ms 运算一次**）。外环跑得慢，从容稳定地进行宏观的路径规划，输出平滑的目标速度给内环。

# 实践指南：双环 PID 的调参顺序

在双环 PID（甚至三环 PID）调参时，控制工程中有一个极其经典且核心的实操原则：**“由内而外，先内后外”**。

即：**必须先断开外环，单独把内环调到最优，然后再闭合外环去调外环。** 绝不能反过来，也不能两个环同时盲调。原因主要有以下三个层面：

## ① 逻辑依赖：“地基”与“上层建筑”的关系

在级联控制中，**内环是外环的“执行器”**。
外环（位置环）计算出“你需要以 20 的速度跑”，这个指令是发给内环（速度环）的。如果内环没有调好（比如响应极其迟钝，或者疯狂抖动），外环发出的任何指令都会被扭曲或延迟。外环再怎么调参也没有意义，因为根本无法准确执行。

## ② 变量解耦：让外环面对一个“理想对象”

当你把内环（速度环）调得极好——达到**“指哪打哪，瞬间响应且无过冲”**的状态时，对于外环来说，**底层复杂的电机物理特性（摩擦力、电感、惯量）就全被内环屏蔽掉了**。

此时，站在外环的角度，内环和电机被打包成了一个**完美的、线性响应的“理想速度执行机构”**。外环调参时，只需要单纯地考虑“距离差多少，我该给多大的速度”，调参难度呈指数级下降。

## ③ 故障排查：避免振荡的“责任推诿”

如果内外环同时调，一旦系统发生剧烈振荡，你会陷入可怕的逻辑死局，无法判断是谁的问题：
* 是外环的 Kp 太大，导致给内环的目标速度一直在疯狂跳动？
* 还是外环给的速度很平稳，但内环的 Kp/Ki 没调好，导致电机自己在抖动？

**“先内后外”的做法完美解决了这个问题：**因为在开启外环前，内环已经被证明是完美的。开启外环后若发生抖动，**100% 是外环参数的问题**。

## 💡 本项目的调参实战步骤

在咱们的定位置控制项目中，如果您需要调参，正确的步骤一定是：

1. **断开外环调内环**：
   在 `main.c` 中注释掉 `InnerTarget = OuterOut;`，直接在代码里或通过电位器手动给 `InnerTarget = 20;`（一个固定的目标速度）。
   调节内环的 `InnerKp`、`InnerKi`，直到电机速度能迅速、平稳地跟随您的设定，且受阻力时能快速恢复。

2. **锁定内环参数**：
   内环参数一旦调好，**绝对不再修改**。

3. **闭合外环调外环**：
   取消注释恢复 `InnerTarget = OuterOut;`，开始给 `OuterTarget` 设定位移目标。
   - 慢慢把外环的 `OuterKp` 加大，直到电机定位迅速。
   - 再加入适量的外环 `OuterKd`，起到“提前刹车”的作用，防止停车过冲。
